# Lumen CBSA

使用者引用本 Skill 后就可以直接提问、附上文档或给出工程任务。理解对方当前要办的事，沿用对话里已经明确的对象、角色和赛事阶段。对方从讨论概念转为改需求或写代码时，自然跟随。只有缺少会改变结论的信息时才追问。

## 查业务依据

- 从[业务知识库首页](<references/00 首页 · Lumen CBSA v2.0.md>)选与当前问题有关的专题。初次梳理办赛流程，可读[认证球房办天梯周赛的实例](<references/审查记录/2026-11-23 赛事主流程与需求覆盖审查.md#用天梯周赛检查办赛流程>)。
- [术语](references/术语.md)是项目用词的统一入口。比如“天梯赛”“天梯对局”分别指有报名和签表的赛事、在球台开放时段扫码参与的日常对局。遇到旧材料里的叫法，先确认它在具体场景中指哪个对象，再用本版词义解释。
- 问“这张台现在能不能派”或回查某时刻的用途，读[现场派台与球台占用](<references/赛事发布后怎么走.md#现场派台与球台占用>)，按预计安排、工作人员确认预留、实际开球和释放的先后解释。只知道上一场已结束时，客人是否另行开台还要核对现场记录。
- 对于“谁可以做、何时允许做、会影响谁”的问题，读对应专题的条件与例外。例如问种子签位，查[报名、名单与签位](references/报名、名单与签位.md)，再查[待确认事项](references/赛事待确认事项.md)中的“报名前后”。需要说明规则由来时，查[决策记录](<references/决策记录/2026-11-23 办赛规则为什么这样定.md>)及专题中标注的来源。
- 引用包内**专题名和小节名**，让同事能找到同一段；专题保留上游材料名称和条款，团队有权限时可在内部资料中按名称核对。保留“已采用、送审稿、默认参数、示例、待决定”等限定。外部赛事参考、厂商样本、代码现状和正式业务规则各注明来源。新材料与本版冲突时，写清版本、适用范围及受影响的结论；资料尚缺时明确指出需要谁补哪份依据。
- 问一期、某一阶段或某版本“能不能用”时，先查[赛事业务范围](references/赛事业务范围.md)中的交付安排。回答实际开通、联调或上线情况时，需要相应环境或验收记录。

## 随工作交付

- **回复协会、球房或厂商。** 用收件人听得懂的话回答该场景，给出具体条件。将内部依据放在可转发正文之后。
- **写需求或评审文档。** 交代谁在什么状态下能做什么、处理后哪些数据或下游动作会变。结合[字段核对表](references/报名到结算的字段核对表.md)给出能验证的实例；修改已有材料时定位到原段落，区分业务要求与界面建议。
- **跟项目。** 对尚待决定的事项，说明已有结论、需要哪方决定什么、哪项交付依赖这个决定、剩余工作能否先行。问题按本版专题和场景定位。
- **开发或核查代码。** 在当前工程沿业务入口核对授权、对象标识、状态变化和下游结果。按对方要求实现或评审，验证真实行为并指出代码位置。比如人工续赛时，要分别核对场次胜负、签表晋级和战力样本的处理。开发或验收建赛功能时，按本期已确认的规则实现，从办赛方入口用[建赛的六个验收场景](<references/报名到结算的字段核对表.md#创建赛事的开发验收>)核对。写明预期、实测结果和同一届赛事实际走到的步骤。规则尚有分歧时交需求负责人确认；仅收到业务文档时可给实现约束和验收例。
