## 天梯赛与赛事系统基础功能

认证球房用“华彩天梯周赛”模板办赛，公开组打单败淘汰。这里，**天梯周赛**是赛事，**华彩十六球**是比赛项目，**公开组**是组别，**单败淘汰**是比赛模式。

| 术语 | 项目中的含义 |
|---|---|
| 赛事、赛事系统基础功能 | 赛事指实际举办的一届比赛，例如某球房本周六的天梯周赛。各类赛事共用的模板配置、建赛、报名、编排、检录、记分、确认名次和归档，统称赛事系统基础功能。 |
| 比赛项目（运动项目）、制胜球（A03） | 比赛项目指打哪种台球。天梯赛采用**华彩十六球**。按该项目规则，选手清完应打的目标球后合法打进制胜球，即赢下本局。**普尔**在本项目中指九球，斯诺克另列。 |
| 华彩天梯（TT、天梯体系） | 包含日常天梯对局、天梯赛、战力、档位、让分等业务的模块。 |
| 天梯赛（天梯赛事） | 按官方模板执行让分规则的赛事。天梯周赛、天梯月赛、天梯季赛、天梯全国赛分别举办，各有报名名单、签表和正式名次。 |
| 开启天梯（A07）、天梯对局 | 认证球房按球台、日期和时段开放日常天梯，称为开启天梯。两名会员在开放时段扫同一张球台的台码打球，称为天梯对局。符合条件的对局用于计算战力。天梯对局无需赛事报名，也没有签表和赛事名次。 |
| 官方赛事、民间赛事 | 说明一场赛事与协会的关系时，分别写明谁主办、是否进入官方赛历、谁授权、是否获认证。民间赛事由办赛方自行组织，也可选用官方模板。计入官方积分榜另有认证和计分要求。 |
| 系列赛（A13）、分站赛事（A14） | 同一系列可包括多站，每一站都是具体的一届赛事，有自己的报名和赛果。本届资格赛出线后的去向由本届规程规定。 |

## 赛历、模板和规程

| 术语 | 项目中的含义 |
|---|---|
| 赛季、年度赛历（官方赛历）、官方赛事计划 | 赛季是划分赛事活动的周期。年度赛历汇总一年的赛事安排，一项官方赛事计划是其中一条安排（赛历条目），例如八月在北京举办一站。每项官方计划至少关联一份赛事模板。 |
| 赛事日程（A18） | 本届报名、报到、抽签、资格赛和正赛等事项的时间。具体到一场球的对手、台号和开球时间，则查赛程。 |
| 赛事模板（办赛模板） | 可反复使用的比赛项目、组别、各轮打法及修改限制等设置。旧稿用“赛事类型”泛指周赛、月赛等类别。建赛时选择的字段叫**赛事模板**，选定后自动带入比赛项目。民间赛事也可不选模板，由办赛方自行填写比赛项目和本届安排。 |
| 官方赛事模板（官方办赛模板）、俱乐部常用模板 | 中台协配置和启用官方模板。办赛方自行选择是否关联官方计划，关联后从计划指定的模板中选。俱乐部常用模板供俱乐部反复选用。对齐稿里的“民间自定义模板”指使用方自行创建或复制调整的配置，开放范围按交付阶段确定。 |
| 预设值（默认值）、固定项、可改范围 | 预设值是模板带入的值。固定项须沿用，开放项只能在允许的范围内调整。例如预设 32 人、允许选 32 或 64 人。每组每阶段首轮的比赛模式和单场局制，模板未固定时须由办赛方明确填写。 |
| 模板版本、模板快照（B16） | 模板版本标识本届选用的那一版。模板快照保存当时的配置内容，供核对本届按什么规则办赛。模板发布普通修订版后，已建赛事继续使用原版。 |
| 竞赛规则、天梯规则、竞赛规程（赛事规程） | 竞赛规则规定怎么打、怎样判犯规和胜负。天梯规则规定如何计战力、评档和让分。竞赛规程由办赛方对本届参赛者公布，写清谁能报、什么时候打、如何晋级和定名次，以及适用的规则。 |
| 规则参数、参数集 | 规则实际使用的数值、表或开关，例如让局表和取样窗口。一起维护的一组参数称为参数集。 |
| 天梯规则版本、参数版本、生效时间、适用范围 | 天梯规则版本记录采用哪一版规则，参数版本记录采用哪一组已发布的数值和表。生效时间说明从何时执行，适用范围说明用于哪些比赛项目、赛事、组织或时段。 |
| 编排版本 | 某次保存的签表和赛程，供比对调整前后的对阵、时间和球台。 |
| 规则确认书 | 由有权人员确认适用规则、参数和算例的文件。 |

<a name="办赛单位、人员与授权"></a>

## 办赛单位、人员与授权

| 术语 | 项目中的含义 |
|---|---|
| 中台协（CBSA）、组织层级、组织树 | 中台协是中国台球协会。组织指协会、球房等单位。组织树记录单位上下级关系，组织层级说明单位所在层次，例如省台协、市台协。 |
| 办赛方、主办方（C04）、承办方（C05） | 办赛方泛指办这届比赛的单位。主办方发起赛事并承担总体责任。承办方依委托或批复具体执行。例如认证球房直接举办天梯周赛，本届主办方按实际发起和组织安排确认，选用中台协模板本身不能认定为中台协主办。 |
| 协办方（C06）、冠名方（C07） | 协办方按约定协助办赛，冠名方按约定获得名称展示。两者实际可操作的赛事数据由授权决定。 |
| 账号、业务身份、角色 | 账号用于登录。业务身份说明登录人现在代表谁，如某球房管理员。角色规定可执行的操作，如确认报名、编排或记分。 |
| 协会会员、单位会员、参赛玩家、选手 | HY 提供既有协会会员资料，单位会员是以单位名义入会的会员。在赛事系统单独注册的人是参赛玩家。选手（参赛者）是本届比赛实际登记的参赛人，成绩记在本人名下。 |
| 职业选手标记 | 标注选手具有职业身份的属性。该选手的档位、能否参赛以及战力是否展示分别按相应规则判断。 |
| 组织授权（C17）、办赛权限（C18）、数据范围 | 组织授权说明某人可代表哪个单位办事。办赛权限说明这个单位及其经办人能创建、发布或管理哪些赛事。数据范围限定能查看或操作的辖区、赛事、组别或场次。首位经办人的授权归属见[赛事待确认事项](赛事待确认事项.md)。 |
| 赛事工作人员（赛事级角色、本届指派，C19） | 办赛方指定某人负责本届报名、编排、检录或记分等工作。建赛时按时段登记到场人手，赛前可再补姓名。 |
| 系统运营、超级管理员、协会授权操作员 | 系统运营负责平台维护，超级管理员按授权管理平台设置。“协会授权操作员”在赛后改分场景中特指中台协指定、在系统中有授权记录的运营人员。 |

## 报名人数和可安排人数

| 术语 | 项目中的含义 |
|---|---|
| 计划参赛人数、正式名额（报名人数上限） | 办赛方打算接收多少人，用计划人数试排。正式名额是本组实际开放的位置总数，例如 32 个。 |
| 可安排人数、最低可安排人数 | 可安排人数由球台、时段、人手和各组打法共同决定。最低可安排人数是官方模板要求具备的容量。例如最低 32 人，试排只能安排 24 人，本届只能存草稿。 |
| 报名资格、报名申请 | 报名资格指选手进入本组应符合的条件，如年龄、档位和会籍。选手或获准代办人提交报名资料，称为报名申请（报名提交）。同一选手一届赛事只报一个组别。 |
| 待定报名、报名确认、确认名单、已确认人数 | 已提交、待处理的申请列入预备名单。办赛方接受报名后，有余位的进确认名单（正式名单），满额的按规程进候补。已确认人数只统计正式名单上的选手。例如上限 32 人、已确认 20 人，还有 12 个正式名额。 |
| 候补名单、候补名额 | 满额后可接收的候补人数叫候补名额。候补名单上的选手等待空位，按规程递补并获确认后才进入正式名单。 |
| 退回重填、拒绝报名、赛事报名拉黑 | 退回重填允许补正资料并重新提交。拒绝报名结束本次申请并说明原因。赛事报名拉黑限制该选手在本届再次申请。 |
| 代报名、监护人、监护关系 | 代办人替实际选手提交报名。监护人为孩子代办时须实名并声明或核验监护关系，报名记录区分代办人和参赛者。 |
| 报名费、线下收款确认 | 报名费是参加本届比赛要交的费用。一期由办赛方在线下核实款项是否到账，正式名额以确认名单为准。 |

## 组别、阶段、轮次、场和局

| 术语 | 项目中的含义 |
|---|---|
| 组别、预设组别 | 组别把同一届赛事的选手分开报名、编排和排名，例如公开组、女子组。预设组别由赛事模板带入。能否新增或替换按模板执行，民间赛事不选模板时自行建组。 |
| 阶段、资格赛、正赛 | 阶段是一组比赛中的一段。资格赛选出进入本届正赛的选手，正赛是争夺本届名次的主体阶段。例如从资格赛选出 16 人进入正赛。 |
| 小组（循环小组） | 同一组别的选手在某个阶段再分成的小组。例如选手报名参加公开组，抽签后进入公开组的 A 小组。 |
| 轮次 | 一个阶段里的一轮对阵，如正赛的 16 进 8、半决赛或决赛。一轮可以分批开打。 |
| 场（场次、赛事场次）、局 | 签表上双方的一次对阵是一场。一局从开球到分出该局胜负。BO5 打成 3 比 1，签表推进 1 场的胜者，记分表留下 4 局的结果。 |
| 杆（上手轮次）、实际击球次数 | 统计杆效时，一杆是选手一次上台连续击球的机会。例如选手连续击打母球 5 次后换人，记 1 杆、5 次实际击球。 |
| 盘（团体赛） | 两队之间的一场比赛可分多盘，每盘由双方各一名队员对阵。PRD v2.1 的后续团体赛方案规定每盘 BO1，一局决定这一盘的胜负。 |

## 每轮的比赛模式和单场局制

| 术语 | 项目中的含义 |
|---|---|
| 轮次赛制 | 每轮分别确定**比赛模式**（赛制）和**单场局制**。比赛模式规定如何配对、淘汰或排名。单场局制规定双方各需赢几局。使用模板时按本轮规定执行官方让局或 BO，民间赛事不选模板时用 BO 平打。 |
| BO（Best of）、抢几、需胜局数 | BO 写最多打几局，“抢几”写先赢几局。一方达到自己的需胜局数，该场结束。BO3 抢 2、BO5 抢 3、BO7 抢 4、BO9 抢 5。采用官方让局时分别记录双方的目标。 |
| 单败淘汰（单淘）、双败淘汰（双败） | 单败输一场即退出该阶段的晋级竞争。32 人单败决出冠军要打 31 场，名次赛另算。双败从胜部开始，首负进败部，再负出局。打到出线还是决出冠军，由规程规定。 |
| 小组循环、同分规则、并列名次 | 单循环中每人与同小组其他选手各打一场。按规程比较小组积分，再用同分规则比较积分相同的选手。规程允许共享名次时才记并列。 |
| 出线、晋级、正赛名额 | 出线指从资格赛或循环小组取得下一阶段的席位。晋级也包括从一轮进入下一轮。正赛名额是正赛能容纳的席位数，包括已分配给资格赛出线者的席位。 |
| 名次赛（排位赛） | 为排定特定名次另打的对阵。例如两名半决赛负者争第三名，胜者第三、负者第四。 |

<a name="对阵、签表和赛程"></a>

## 对阵、签表和赛程

| 术语 | 项目中的含义 |
|---|---|
| 对阵、签表、签位 | 对阵是某场由谁对谁。签表列出各轮对阵和胜负后去向，签位是签表中的一个位置。例如八强赛的一个签位留给“A 小组第一名”。 |
| 编排、抽签、落位 | 编排按本届赛制和名单形成各轮对阵。抽签是按公布的办法确定位置，落位是把选手或晋级来源填进签位。抽签可在线下进行，再录入结果。 |
| 种子选手、蛇形落位、回避 | 种子按规程指定的依据选出并分散落位。蛇形落位是把选手按顺序在各小组间往返分配。抽签回避限制特定选手过早相遇，如同球房选手首轮尽量避开。裁判回避另指某人避开执裁特定场次。 |
| 晋级来源、待定对手、空签位 | “资格赛第一名”是晋级来源，有来源但姓名还未确定的是待定对手。空签位表示暂未放入选手或指定来源，需按编排结果判断如何处理。 |
| 轮空 | 依签表无需实际对阵就进入下一轮。10 人排进 16 签，首轮 6 人轮空、其余 4 人打 2 场。轮空不占台、不记比分。已有对手后来退出，按退赛或弃权记录。 |
| 名额递补 | 已分配的参赛席位出现空缺，按本届规则和顺序补入符合条件的人，名额总数不变。 |
| 赛程（赛事赛程）、排台（排桌、赛程调度） | 发布的赛程写明每场的日期、预计开球时间和计划台号。排台是把一场对阵安排到具体球台和时段。例如“周六 10:00，3 号台，公开组半决赛”。 |
| 预排（试排）、正式对阵 | 建赛时用计划人数和空签表试排，检查球台、人手和时段，估算能收多少人、几点打完。名单确认后，再把实际选手排入正式对阵。 |
| 赛事发布、报名开放、赛程发布 | 发布赛事是公开本届办赛信息。报名开放是到了可以提交申请的时间。发布赛程是公布各场的时间、球台和对手或晋级来源。 |

## 球房、场馆和设备

| 术语 | 项目中的含义 |

## 天梯档位、战力与让分

| 术语 | 项目中的含义 |
|---|---|
| 天梯档位（D 档）、段位组 | 按默认映射，D2、D3 是两个具体档位，都属于“白银”段位组。对外称“档位”，可显示为“D3 白银”。**档差**是双方 D 档相差的档数。 |
| 实时档位、档位快照 | 实时档位是选手此刻的档位，快照是为某次业务保留下来的档位。**报名档位**取提交报名时的值，用于检查参赛资格。**开球档位**取这场比赛开球前扫码时的值，用于让局、让球。**开赛档位**指赛事开赛时的值，涉及种子排序。提前公布签表时的取值时点仍待确认。 |
| 未定档、考级映射 | 选手尚无天梯档位时平打，取得档位后按当场档位让分。考级映射指按协会的对应表，把考级结果换算成天梯档位。PX 的**技能等级、技术等级**是两项外部记录，映射时核对协会指定的字段和对应表。 |
| 战力（战力指数，ZL）、单次战力结果 | 用有效比赛数据算出的天梯水平指标。赛事按一场对阵算一次，日常天梯按双方在同一球台连续打的一次扫码对局算一次。计算时汇总其中符合条件的局。 |
| 有效对局、有效样本 | 完赛对局符合场地、设备、数据和局数等条件，才能成为定档用的**有效记录**。娱乐局、争议局和未完成局从该次统计中剔除。C 档球台现场记分按当前反馈作娱乐处理，产品需求保留计战力开关。工作人员确认的胜负仍可用于赛事晋级。[有效记录的条件](<赛事档位、战力与让分.md#计入战力的有效记录>) |
| 定档成绩、取样窗口、取样数、候补样本 | 取样窗口规定成绩的有效期。取样数规定用几场。系统在有效期内按规则选出较高的单次战力，按取样表计算定档成绩，再对照区间表确定 D 档。候补样本在入选场次失效时可递入。 |
| 升档、降档、人工调档 | 定档成绩对应的 D 档提高叫升档，降低叫降档。人工调档是中台协处理会员调档申诉时更正其档位，操作留痕。 |
| 战力流水、压级、防压级 | 战力流水记录战力取自哪场、何时生成或修正。压级指故意压低记录或档位以获得让分优势。防压级措施用于发现可疑场次并提交复核。 |

战力公式中的缩写按产品需求 v2.1 使用。各项的默认值、零胜局处理和取样算例见[赛事档位、战力与让分](<赛事档位、战力与让分.md#从战力取样到确定档位>)。

| 公式术语 | 含义 |
|---|---|
| PJG（平均获胜杆数，O01）、GX（杆效项，O02） | PJG 是本次统计的总杆数除以总胜局数，一杆按一次上手计算。GX 用 PJG 衡量赢一局的杆数效率。 |
| SL（胜率项，O03）、SC（累计胜局项，O04） | SL 用本次有效胜局数除以有效总局数。SC 看累计胜局数相对参考值的比例，达到上限后取 1。 |
| B、K、N_sc、权重 | B 是杆效基准，K 是杆效计算的封顶系数，N_sc 是累计胜局参考值。权重决定 GX、SL、SC 各自在 ZL 中占多少。 |

| 让分术语 | 比赛中怎样使用 |
|---|---|
| 让分、官方让局、单局让球、平打 | 让分包括两种办法。让局规定双方整场各要赢几局，让球规定受让方在一局里何时拿走几颗己方目标球。**受让方**得到让步，**让分方**作出让步。让局、让球的办法均由本届赛事模板规定，办赛方不能自定。例如华彩天梯周赛按 9 局 5 胜的官方让局表，D5 对 D3 时双方分别需胜 5 局和 3 局。平打时双方按相同的胜局目标和用球条件比赛。 |
| 首局让球（让球基线）、动态让球 | 首局让球按模板查低档方所在档组和双方档差。模板启用动态让球时，再按上一局结果调整下一局的让球级别，本场双方的胜局目标保持不变。 |
| 前一、中一、后一、后二 | **前一**在分清花色后，受让方将己方 1 颗球拿起放进袋。**中一**在己方剩 4 颗时拿走 1 颗。**后一**在剩 2 颗时选 1 颗打，把另 1 颗放进袋。**后二**在剩 3 颗时选 1 颗打，把另 2 颗放进袋。 |
| 娱乐局、娱乐场次 | 按天梯规则只记比赛结果的局或场次，例如双方档差超出计战力范围。赛事中仍按正式胜负推进签表。 |
| 天梯权益、免费策略 | 天梯权益指会员在有效期内参加天梯活动的资格。免费策略规定哪些人、在哪些地区或时段可以免费取得权益。报名时仍按赛事要求核验其他资格。 |
| 分档奖金、奖金系数 | 附件 4 的分档奖金办法按选手档位折算奖金，奖金系数是乘在原定名次奖金上的比例。**一期奖金说明**是办赛方写给参赛者的文字，具体金额和发放由办赛方处理。 |

### 比分、成绩与更正

| 术语 | 项目中的含义 |
|---|---|
| 比分、局结果、场次结果 | 比分记录比赛进展。局结果记这一局的胜方。场次结果记整场谁胜、局比分和结束方式。例如场比分 2∶1 时已经有三局结果，最终场次胜方还要看谁先达到需胜局数。 |
| 弃权、判负 | 选手放弃本场参赛机会称弃权。裁决人员依规程认定一方负于对手称判负。退出本届赛事称退赛。三种情形分别记录原因。 |
| 完赛、成绩生效、成绩锁定 | 完赛要指明是哪一场、哪一组或整届结束。单场结果生效后可用于推进签表。单场完赛后锁定正式成绩，赛后改分按专门权限办理。战力与赛事积分各按本项规则结算。 |
| 复核、最终名次、正式成绩 | 复核是有权人员核对记分与裁决。赛制和比赛结果决定组内最终名次。正式成绩是经规定程序生效的结果，例如已判定的单场胜负和已确认的组内名次。 |
| 赛事成绩确认、归档、赛事报告 | 负责人按组确认名次，叫作赛事成绩确认。全部组别办理完毕后整届归档，保存签表、正式成绩和赛事报告。报告汇总本届成绩及办赛情况。 |
| 申诉、举报、争议记录、待复核 | 选手对与自己有关的判定提出异议称申诉，报告涉嫌违规线索称举报。争议记录写明哪一局、哪项判定有异议。待复核表示还要由有权人员核实。 |
| 改分（成绩更正）、回溯重算 | 改分更正已锁定的正式成绩。更正后生成新的**成绩版本**（成绩修正版本），保留原比分、原因、操作人和时间。通常由上级协会或中台协申请，另一名获授权人员执行或驳回。回溯重算是据更正结果重新核算受影响的战力、后续让分、晋级、名次和积分。 |
| 处罚、禁赛、账号冻结 | 处罚是对违规行为的处理。禁赛限制参赛，账号冻结限制账号使用。冻结赛事积分结算时，暂停处理的是该届积分。 |
| 赛事参与评价、办赛信用分 | 参赛者对办赛体验给出的反馈称赛事参与评价。办赛信用分按规则汇总办赛评价，用来衡量办赛主体的表现。 |

| 承办招募、赛事申办（承办申请）、批复 | 主办方公开征集承办单位，意向单位提交场地、时间与办赛方案，有权单位作出批复。申请人是单位，申请的是承办资格。 |
| 指定承办、赛事招标、中标确认 | 指定承办由有权单位直接确定承办方。采用招标时，各单位投标，由组织方评审并确认中标单位。线上招标的交付范围以协会签认为准。 |
| 赛事登记、认证申报 | 登记是报送本届赛事信息。申请相应认证须另行申报，以评定结果为准。[民间赛事认证与积分](民间赛事认证与积分.md) |
| 积分直通、推荐名额、外卡 | 三种参赛席位来源，分别凭规定的积分资格、单位推荐或赛事特别授予的资格进入。适用条件、名额和审批按本届规程执行。 |
| 团体赛、参赛队伍 | 团体赛以队伍为对阵双方。一支参赛队伍由本届登记的队员组成，按团体赛规程安排各盘出场人选。 |
| 战队、队长排阵、转会窗口 | 战队可以跨届保有成员。队长为某场比赛安排出场人选和顺序，称为排阵。转会窗口是允许变更战队归属的时间段。 |
| 个人挑战、挑战活动、挑战题目 | 单名会员在活动规定的时间内完成一道题目。活动规定参与范围和周期，题目规定动作及计分方式，完成后得到本次挑战成绩。 |
| 线上约战、自动匹配 | 线上约战由一方发出、另一方接受邀约。自动匹配由系统配对对手。球房里两名会员扫同一桌码打球称为天梯对局。 |

## 系统简称与记分数据

| 简称 | 对应业务 |
|---|---|
| SS、MS、TT（M01） | SS 是赛事系统，管报名、签表和正式赛果。MS 是共用的对局会话层，把选手、球台和逐局记录连起来。TT 是华彩天梯，管战力、档位和让分等业务。 |
| JF 记分系统、HY、PX、MH | JF 指接入的第三方记分系统。HY 提供既有会员身份和角色，PX 提供培训考级资料，MH 是对外展示信息的门户。 |
| RF、PC、PT（M02） | RF 是裁判模块，PC 是个人挑战，PT 管积分与成长。 |
| FW、ADM | FW 是会员小程序。ADM 包括机构管理端、办赛人员使用的现场端，以及用于对外查询和现场展示的公开站与大屏。现场端 PWA 指可在浏览器中使用的现场应用。 |
| BASE、EXT、SEC | BASE 是账号、权限、参数等公共底座。EXT 管外部系统对接。SEC 指安全相关能力。 |

**同一张球台上的三种记录。** 签表安排的是赛事场次；扫码后，MS 用对局会话（M07）关联本场的人和球台；每局结束后，局记录保存该局次、胜方和判定来源。换台续记时仍须对上原场。[场次、对局与局记录](概念/场次、对局与局记录.md)

> [!info]- 会话、采集与数据核对
>
> | 术语 | 含义 |
> |---|---|
> | 采集会话（M08）、登录会话（M09） | 采集会话是 JF 组织一次采集的记录，与 MS 对局会话的编号对应关系按对接协议核对。设备重连后即使新建采集记录，也要与原场、原局次对上。登录会话记录用户在哪台设备登录以及登录是否有效。 |
> | 原子事件、击球摘要 | 原子事件记录球位、移动或碰撞等一次观测。击球摘要汇总一次实际击球的过程和结果。 |
> | 设备事实、引擎判定、人工裁决（M11） | 设备记录台面发生了什么，引擎根据规则判定结果，有权限的人处理现场争议。核对比分时要能查到结果来源。 |
> | 数据完整性、完整性清单 | 完整性表示规定要交付的局、击球等记录是否齐备。清单用于逐项核对缺失记录。仅有最终比分时，仍可能缺少计算战力的数据。 |
> | 端离线、设备离线、补传与补拉（M14） | 端离线指现场端连接中断，设备离线指采集设备通信中断。恢复后由发送方重发叫补传，由接收方主动取回叫补拉。 |
> | 去重、幂等（M15） | 去重是识别两份数据是否来自同一条记录。幂等是同一操作重复执行仍只生效一次，例如同一局补传两次，比分只加一次。 |
> | 数据修订、作废、冲突（M16） | 修订保留新旧值的关系，作废标明旧记录失效。不同来源的记录互相矛盾时，须核对原场、局次、来源与修订依据。涉及正式成绩的修订见[锁定后的改分权限](<现场续赛、申诉与改分.md#正式成绩锁定后的改分权限>)。 |
> | 录像、录像索引、证据保全（M18） | 录像是视频文件。索引把视频片段对应到场次、局次和时间点。发生争议时依规定保留相关证据，称为证据保全。用录像复核胜负后，计战力仍须核对规定的采集字段。 |
> | 主数据、系统字典（枚举） | 组织、会员、球房和球台是多项业务共用的主数据。系统字典规定一个字段能选哪些值，例如比赛项目或行政区划。 |

## 发布、联调与交付用语

| 术语 | 含义 |
|---|---|
| 草稿、待审核、已发布 | 草稿可以继续填写。需要赛事发布审核时，提交后由有权单位决定能否发布；获准免审的赛事可直接发布。已发布表示赛事信息已对外可见。 |
| 必填、条件必填、选填、必有值 | 必填要求经办人在指定步骤填齐。条件必填在条件成立时才要求填写。选填允许留空。必有值强调办理时必须有确定值，模板也可以直接带入，例如选模板建赛时的比赛项目。 |
| 未填、未知、不限、不适用、否 | 未填表示还没给值，未知表示尚无法核实，不限表示明确允许任意合规取值，不适用表示这个场景用不到该项，否表示已经明确作出否定选择。 |

> [!info]- 查研发、对接与验收用词
>
> | 术语 | 含义 |
> |---|---|
> | 主身份、会员号、手机号（O07） | 主身份用于跨业务识别同一人，会员号标识会员档案，手机号用作联系方式或登录信息。换手机号时仍须认回原档案。 |
> | 接口、回调、单点登录（SSO） | 接口约定系统间交换什么数据。回调是对方主动推送约定的事件。单点登录指一次登录后由接入的多个系统共享认证。 |
> | 测试环境、预发布环境、生产环境（N07） | 分别用于受控测试、上线前验证和正式业务运行。 |
> | 测试赛、沙箱（N08） | 测试赛是用于演练的赛事。沙箱把它产生的记录与正式业务隔开，例如测试赛成绩留在沙箱。 |
> | 联调、模拟数据、真实设备实测（N09） | 联调检查多个系统能否按约定交换和处理数据。模拟数据是人为构造的输入，真实设备实测要用现场设备采集和回传。 |
> | 灰度、验收（N10） | 灰度让限定范围内的实际用户先使用系统。验收按已确定的业务标准和运行结果判断是否通过。说明验证进度时写明环境及对应的运行或验收记录。 |
> | 审计日志、变更留痕 | 审计日志记录谁在何时以何种身份做了什么。变更留痕还要能查到原值和新值，例如改分前后的比分。 |
> | 站内信、订阅消息、短信 | 站内信在系统里查收，订阅消息经微信送达，短信发送到手机号。 |
> | PRD、FR、BR、需求优先级 | PRD 是产品需求文档，FR 标识功能需求，BR 标识业务规则。P0、P1、P2 表示优先级，交付阶段另查正式范围。 |
> | 域名、HTTPS、证书 | 域名是访问服务的名称，HTTPS 加密传输数据，网站证书用于校验服务身份。 |
> | ICP备案、小程序备案与认证 | ICP 备案登记互联网信息服务资料。小程序备案登记小程序及主办者，平台认证核验主体身份。 |
> | 等保三级、密评 | 等保三级指网络安全等级保护第三级。密评是商用密码应用安全性评估。 |
> | 对象存储、CDN | 对象存储保存录像等文件，CDN 用于加快分发。录像的播放地址和归档位置可以不同。 |
> | 资金结算、商户号、退款 | 资金结算处理实际款项，商户号是支付系统中的商户标识，退款是退回已收款项。一期赛事系统记录办赛方线下收款确认。 |

> [!info]- 对照旧资料中的叫法
> - “赛事实例”指具体一届赛事。“挂靠赛历”在建赛时指关联官方赛事计划。旧稿写“办赛计划”时，要看它指全年安排还是具体某一站。
> - “天梯日赛／天梯日常赛”如果指两名会员在球房日常扫码打球，本库称“天梯对局”。“自动排赛历／赛历拖拽”如果指安排或调整逐场时间和球台，本库称“排赛程／调整赛程”。
> - “办赛规则模板”如果指可复用的办赛配置，本库称“赛事模板”。规程文本模板供起草本届竞赛规程。“版本规则”要写明是天梯规则版本还是参数版本。
> - 旧稿的“五场评估周期”是历史方案用语。核对当前定档办法时，查本版的取样窗口、取样数和有效样本。
